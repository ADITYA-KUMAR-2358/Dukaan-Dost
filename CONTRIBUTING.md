# Contributing

1. Read `docs/DEVELOPMENT_SPEC.md`, `docs/RULES.md`, and `docs/TASKS.md`.
2. Keep forecasts honest. A baseline must never be labelled TabPFN.
3. Do not commit `.env`, shop databases, sample-shop mixes with real sales, or model weights.
4. Add or update tests for the behaviour you change.
5. Run backend `ruff` and `pytest`, then frontend `npm test`, `npm run typecheck`, `npm run lint`, and `npm run build`.

Pull requests should say what was verified and what was not.
